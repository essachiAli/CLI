Simple Git CLI 🚀
A lightweight command-line interface (CLI) application built with PHP and Composer, designed to emulate a simplified version of the git help command. This project leverages PSR-4 autoloading for modular code organization and implements exception-based error handling, serving as an educational tool for PHP CLI development.
Features ✨

📜 Displays general help with usage instructions and a list of common Git commands (clone, init, status).
ℹ️ Provides detailed help for specific commands when invoked with the help command and a subcommand.
🏷️ Supports a --version or -v flag to display version information (git version 1.0.0).
🛠️ Utilizes PSR-4 autoloading for efficient class management.
🚫 Employs exception handling for robust error reporting (e.g., unknown commands or subcommands).
🔄 Dependency-free, relying solely on PHP's built-in argument parsing capabilities.

Prerequisites 📋

🐘 PHP 7.4 or higher
📦 Composer (available at getcomposer.org)

Installation 🛠️

Clone the Repository:Clone this repository to your local machine or create a new directory for the project.

Initialize Composer:Navigate to the project directory and run the Composer initialization command. Provide the following details:

Package name: e.g., yourname/simple-git-cli
Description: "A simple CLI mimicking git help with exception handling"
Author: Your name
License: MIT
Dependencies: Skip by pressing Enter, as no external dependencies are required.


Configure PSR-4 Autoloading:Update the composer.json file to include PSR-4 autoloading, mapping the App\ namespace to the src/ directory. Generate the autoloader using the appropriate Composer command.

Set Up Directory Structure:Ensure the project includes the following structure:

src/Commands/ for command classes
bin/ for the executable script
composer.json, composer.lock, and vendor/ generated by Composer


Create the CLI Executable:Add an executable script named git.php in the bin/ directory to load the autoloader, parse arguments, handle the version flag, and execute commands with exception handling.

Implement the Help Command:Create a HelpCommand class in the src/Commands/ directory to manage the help command, display general or specific command help, and throw exceptions for invalid inputs.


Usage 📖
Run commands from the project directory using PHP:

General Help: Execute the main script without arguments to display usage instructions and a list of supported commands (clone, init, status).
Specific Command Help: Run the script with the help command followed by a subcommand (e.g., clone) to view detailed help for that command.
Version Information: Use the --version or -v flag to display the application version (git version 1.0.0).
Error Handling: Invalid commands or subcommands trigger error messages (output to stderr) with guidance on correct usage.

Development Notes 📝

PSR-4 Autoloading: The App\ namespace maps to the src/ directory, enabling seamless class loading for a clean and maintainable codebase.
Exception Handling: Errors, such as unrecognized commands, are managed through exceptions, caught in the main script, and displayed to stderr for user-friendly feedback.
No External Dependencies: The application uses PHP's built-in argument parsing functions, ensuring simplicity and portability.

Troubleshooting 🛠️

PSR-4 Autoloading Issues:
Verify that namespaces align with directory paths (e.g., App\Commands corresponds to src/Commands/).
Regenerate the autoloader after adding new files.
Ensure file and class names are case-sensitive matches.


CLI Execution Issues:
Confirm the executable script has proper permissions and includes the correct shebang line.
Debug argument parsing by inspecting command-line inputs.


Autoloading Verification:Create a test script to instantiate the HelpCommand class and validate PSR-4 autoloading functionality.
